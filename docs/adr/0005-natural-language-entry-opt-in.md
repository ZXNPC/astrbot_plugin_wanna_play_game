# 0005 - 自然语言入口改为配置开关，默认关闭

## Status

Accepted

## Context

原实现无条件注册自然语言入口：用户发送匹配
`^(?:我想玩(?:一下)?|我要玩)\s*[:：]?\s*(.+?)[。！？!?.,，\s]*$` 的消息即触发检索。
该模式只做前缀匹配，不判断 `(.+?)` 是否是游戏名，因此日常闲聊会被整句吃掉：

- 「我想玩点好玩的」→ 游戏名「点好玩的」→ 两次真实的站点检索请求与一条无关回复。
- 群聊中这类表达高频出现，误触发既打扰用户，也会给 gamer520.com 与 online-fix.me
  带来无谓请求（命中率极低，还会写入 24 小时缓存）。

命令入口 `/game xxx` 有显式前缀，不存在同类误判。

## Decision

- 新增配置项 `enable_nl_trigger`（`bool`，默认 `false`）：仅当用户显式开启时，
  `filter.regex` 的自然语言 handler 才解析并检索；关闭时该 handler 直接返回，
  消息继续走 AstrBot 常规链路（LLM 或其他插件）。
- `/game xxx` 命令入口始终可用；开启自然语言入口后两个入口等效。
- `/game` 无参数时的用法提示按开关调整：关闭时不再宣传「我想玩 xxx」入口。
- 触发解析（自然语言与命令两套模式）移入 `app/trigger.py`，使默认关闭这一行为
  及其误判边界可以在没有 AstrBot 运行时的单元测试中固定下来。

## Consequences

- 默认行为变化：升级后「我想玩 xxx」不再触发，依赖该入口的用户需在 WebUI 插件配置中开启。
- 开启后「我想玩点好玩的」仍会被解析成「点好玩的」——本 ADR 只把误触发的默认面收敛为关闭，
  没有引入游戏名识别（沿用 ADR-0003：不做名称解析/翻译，保持零 LLM 依赖）。
- 若将来要在开启状态下进一步降噪，可在 `app/trigger.py` 增加轻量启发式（如疑问/指代词过滤），
  测试已覆盖现有误判样例。
